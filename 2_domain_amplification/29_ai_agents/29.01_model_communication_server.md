# AI Model Communication Server Guide

## Overview
This document compiles information on integrating AI models (via OpenRouter or API keys) into Discord bots and structuring a mini server for inter-model communication. Based on discussions about running models as Discord bots and enabling models to talk to each other.

## Part 1: Running AI Models as Discord Bots

### Key Components
- **Discord Bot Framework**: Use discord.py (Python) or discord.js (Node.js) for bot implementation.
- **API Integration**: Connect to OpenRouter, OpenAI, or similar services using API keys.
- **Model Selection**: Choose models like Claude, GPT, or Llama via endpoints.
- **Hosting**: Run locally or on cloud platforms (Heroku, VPS, Replit).

### Basic Implementation (Python with discord.py)
```python
import discord
from discord.ext import commands
import requests
import os

# Environment variables for security
DISCORD_TOKEN = os.getenv('DISCORD_TOKEN')
OPENROUTER_API_KEY = os.getenv('OPENROUTER_API_KEY')

bot = commands.Bot(command_prefix='!', intents=discord.Intents.default())

@bot.event
async def on_ready():
    print(f'{bot.user} has landed!')

@bot.command(name='ask')
async def ask_model(ctx, *, query: str):
    try:
        response = requests.post(
            'https://openrouter.ai/api/v1/chat/completions',
            headers={
                'Authorization': f'Bearer {OPENROUTER_API_KEY}',
                'Content-Type': 'application/json'
            },
            json={
                'model': 'anthropic/claude-3.5-sonnet',  # Or any available model
                'messages': [{'role': 'user', 'content': query}],
                'max_tokens': 500
            },
            timeout=30
        )
        response.raise_for_status()
        result = response.json()['choices'][0]['message']['content']
        await ctx.send(result[:2000])  # Discord message limit
    except Exception as e:
        await ctx.send(f'Error: {str(e)}')

bot.run(DISCORD_TOKEN)
```

### Setup Steps
1. Create a Discord application and bot at https://discord.com/developers/applications.
2. Install dependencies: `pip install discord.py requests`.
3. Set environment variables for tokens and API keys.
4. Invite bot to server with message permissions.
5. Run the bot: `python bot.py`.
6. Test with `!ask Hello, how are you?`.

### Enhancements
- **Error Handling**: Add retries, rate limiting (e.g., using `ratelimit` library).
- **Context Management**: Store conversation history in a database (SQLite/Redis).
- **Multiple Models**: Add commands to switch models (e.g., `!model gpt-4`).
- **Security**: Validate inputs to prevent prompt injection; use async for scalability.

### Key Components

#### 1. Model Registry
Manages available models, their endpoints, and capabilities.
```python
import json
from typing import Dict, List

class ModelRegistry:
    def __init__(self, registry_file: str = 'models.json'):
        self.models: Dict[str, Dict] = {}
        self.load_registry(registry_file)
    
    def load_registry(self, file_path: str):
        try:
            with open(file_path, 'r') as f:
                self.models = json.load(f)
        except FileNotFoundError:
            self.models = {}
    
    def register_model(self, model_id: str, endpoint: str, capabilities: List[str], config: Dict):
        self.models[model_id] = {
            'endpoint': endpoint,
            'capabilities': capabilities,
            'config': config,
            'status': 'active'
        }
        self.save_registry()
    
    def find_models(self, capability: str) -> List[str]:
        return [mid for mid, data in self.models.items() 
                if capability in data['capabilities'] and data['status'] == 'active']
    
    def save_registry(self):
        # Save to JSON file
        pass  # Implementation details
```

#### 2. Message Broker
Handles asynchronous communication between models.
- **Options**: Redis (pub/sub), RabbitMQ (queues), or in-memory for simple setups.
```python
import redis
import json
from typing import Any

class RedisMessageBroker:
    def __init__(self, host='localhost', port=6379, db=0):
        self.client = redis.Redis(host=host, port=port, db=db)
    
    def publish(self, channel: str, message: Dict[str, Any]):
        self.client.publish(channel, json.dumps(message))
    
    def subscribe(self, channel: str, callback):
        pubsub = self.client.pubsub()
        pubsub.subscribe(channel)
        for message in pubsub.listen():
            if message['type'] == 'message':
                data = json.loads(message['data'])
                callback(data)
```

#### 3. Orchestrator
Coordinates workflows, routing messages between models.
```python
class Orchestrator:
    def __init__(self, registry: ModelRegistry, broker: RedisMessageBroker):
        self.registry = registry
        self.broker = broker
        self.workflows = {}  # Define workflows like 'debate', 'code_review'
    
    async def run_workflow(self, workflow_type: str, initial_input: Dict):
        models = self.get_workflow_models(workflow_type)
        state = {'input': initial_input, 'history': []}
        
        for model_id in models:
            model = self.registry.get_model(model_id)
            response = await self.call_model(model, state)
            state['history'].append(response)
            self.broker.publish(f'{workflow_type}_next', {'state': state, 'next_model': models[(models.index(model_id) + 1) % len(models)]})
        
        return state
    
    async def call_model(self, model: Dict, state: Dict) -> Dict:
        # API call to model endpoint with state as prompt
        # Example using requests
        response = requests.post(model['endpoint'], json={'prompt': self.build_prompt(state)})
        return {'model_id': model['id'], 'output': response.json()}
```

#### 4. API Gateway
Exposes endpoints for external triggers (e.g., Discord bot integration).
- Use FastAPI or Flask for REST/WebSocket.
```python
from fastapi import FastAPI
from orchestrator import Orchestrator

app = FastAPI()
orchestrator = Orchestrator(...)  # Initialized

@app.post("/start-workflow/{workflow_type}")
async def start_workflow(workflow_type: str, input_data: Dict):
    result = await orchestrator.run_workflow(workflow_type, input_data)
    return result

@app.websocket("/ws-chat")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()
    while True:
        data = await websocket.receive_text()
        # Trigger workflow and stream responses
        await websocket.send_text("Processing...")
```

### Implementation Steps
1. **Setup Environment**: Install dependencies (`pip install redis fastapi uvicorn requests`).
2. **Configure Models**: Populate `models.json` with OpenRouter endpoints and capabilities (e.g., "reasoning", "coding").
3. **Define Workflows**: Create JSON configs for sequences like Model A → Model B → Model C.
4. **Run Broker**: Start Redis/RabbitMQ.
5. **Launch Server**: `uvicorn main:app --reload`.
6. **Integrate with Discord**: Bot sends requests to `/start-workflow/debate` endpoint.

### Example Use Case: Debate Workflow
- Model A (Philosopher): Generates initial argument.
- Model B (Critic): Responds with counterpoints.
- Model C (Synthesizer): Resolves and summarizes.
- Output: Balanced discussion via message broker.

### Challenges & Solutions
- **Latency**: Use async calls and caching.
- **Cost**: Monitor API usage; implement quotas.
- **State Management**: Use Redis for persistence.
- **Error Recovery**: Retry failed model calls; fallback models.
- **Scalability**: Containerize with Docker; orchestrate with Kubernetes for production.

### Tech Stack Recommendations
- **Backend**: Python (FastAPI), Node.js (Express).
- **Broker**: Redis (simple), RabbitMQ (robust).
- **Database**: SQLite (dev), PostgreSQL (prod) for logs.
- **Deployment**: Docker Compose for local; AWS/EC2 for cloud.

This setup enables modular, scalable AI agent interactions. Extend by adding more models or complex routing logic.
