# Local TTS Feasibility: Coqui AI (XTTS-v2) & Alternatives for NEUROMANCER Agent

## Overview
This document provides a deep dive into Coqui AI's TTS technology, feasibility on MacBook Pro M4 Pro (24GB unified memory), alternative local TTS options (2024-2025 era), and integration strategies for the NEUROMANCER semi-autonomous AI agent (per skeleton in 20250923_221125_project_skeleton_NEUROMANCER_Agent.md). Focus: Offline, low-latency voice output for Jarvis-like conversational interface.

## Coqui AI Company Deep Dive
Coqui AI (founded 2019, shut down July 2023) was an open-source speech AI company originating from Mozilla's TTS/STT projects. It specialized in accessible TTS/STT tools, raising ~$15M from NVIDIA and others. Founders: Erik de Vries (CEO), Enea Ceolini (CTO). Shutdown due to funding challenges; all assets released under MPL-2.0 for community maintenance.

- **Key Repos**: [TTS](https://github.com/coqui-ai/TTS) (42k stars, last update Aug 2024); [XTTS-v2 on HF](https://huggingface.co/coqui/XTTS-v2) (5M+ downloads).
- **No Major Controversies**: Ethical guidelines for deepfakes (e.g., watermarking); community-driven post-shutdown.

## Coqui TTS Technology: XTTS-v2
Flagship model: XTTS-v2 (2023), a multilingual voice cloning TTS.
- **Architecture**: VITS-based with GPT-style conditioning, diffusion vocoder, GE2E embeddings. Supports spectrogram gen (Glow-TTS/FastSpeech2) + HiFi-GAN vocoding.
- **Features**:
  - Zero-shot cloning (6s audio clip).
  - 17 languages (en, es, fr, de, it, pt, pl, tr, ru, nl, cs, ar, zh-cn, ja, hu, ko, hi).
  - Cross-lingual cloning, emotion transfer, 24kHz output, real-time streaming (<200ms latency).
- **Other Models**: YourTTS (multilingual), Bark (generative), Tortoise (high-fid).
- **Usage Example**:
  ```python
  from TTS.api import TTS
  tts = TTS("tts_models/multilingual/multi-dataset/xtts_v2").to("mps")  # MPS for Apple Silicon
  tts.tts_to_file(text="Hello world!", speaker_wav="clip.wav", language="en", file_path="output.wav")
  ```
- **CLI**: `tts --model_name tts_models/multilingual/multi-dataset/xtts_v2 --text "Text" --speaker_wav clip.wav --language en --out_path output.wav`.

## Feasibility on MacBook Pro M4 Pro (24GB Unified Memory)
**High Feasibility**: XTTS-v2 (~1.2GB quantized) leverages PyTorch's MPS backend for Neural Engine acceleration. Install: `pip install TTS` (torch with MPS support).
- **Performance**: <200ms inference for short clips; initial load 5-10s. 24GB handles model + context/batching easily (peak ~4GB).
- **Setup**: `device = "mps" if torch.backends.mps.is_available() else "cpu"`. Fine-tuning viable with LoRA (add ~2-4GB RAM).
- **Limits**: GPU-heavy for long audio; test on macOS Sonoma+ (no Ventura issues reported).
- **Comparisons**:
  | Competitor | Open-Source | Cloning | Languages | Speed on M4 Pro | Pricing |
  |------------|-------------|---------|-----------|-----------------|---------|
  | **ElevenLabs** | No | Instant (1000+ voices) | 29+ | N/A (API) | $0.18/1k chars |
  | **Google TTS** | No | Custom (10s+) | 50+ | N/A (cloud) | $4-16/M chars |

## Other Local TTS Options (Recent, ~2025)
Open-source, offline models runnable on M4 Pro (MPS/CPU; 16GB+ viable, 24GB optimal). All via PyTorch/ONNX.

| Model/Tool | Release/Features | Size/Latency on M4 Pro | Feasibility/Pros | Cons/Notes |
|------------|------------------|------------------------|------------------|------------|
| **Piper TTS** (Rhasspy, 2024) | Fast neural; 100+ voices/langs; ONNX. | ~50-200MB; <50ms. | Excellent: Lightweight, always-on. `pip install piper-tts`. | Basic prosody; no advanced cloning. |
| **Parler-TTS** (HF, 2024) | Prompt-based styles; 1B params. | ~2GB; 100-300ms. | High: Custom voices; MPS fine-tune. | English-primary; slower for long text. |
| **StyleTTS 2** (2023-24) | Zero-shot style; en/zh multilingual. | ~500MB; 150-400ms. | Good: Natural prosody; HF integration. | Training compute-intensive. |
| **Bark** (Suno, 2023-24 forks) | Generative speech/music. | ~1GB; 200-500ms. | Medium-High: Creative; quantize for speed. | Noisy; higher RAM (~6GB peak). |
| **MMS-TTS** (Meta, 2023-25) | 1100+ langs; efficient. | ~300MB/lang; <100ms. | High: Rare lang support; ONNX export. | Basic quality; extend for cloning. |
| **Tortoise TTS** (2023 forks) | High-fid cloning; autoregressive. | ~2GB; 1-5s. | Medium: Offline gen; MPS viable. | Not real-time; batch optimize. |

Prioritize: Piper (speed), XTTS (cloning), Parler (customization). Install: `pip install torch --index-url https://download.pytorch.org/whl/nightly/cpu` for MPS.

## Integration into NEUROMANCER Agent (Jarvis-Type, Semi-Autonomous)
Aligns with skeleton: Add TTS to `src/agent.py` for voice in conversational interface (pair with Whisper STT). Maintains local/always-on (Ollama + ChromaDB).

### Steps
1. **Update requirements.txt**: Add `TTS` (Coqui) or `piper-tts`; `openai-whisper` for STT; `pygame` or macOS `afplay` for playback.
2. **Core Code** (in `src/agent.py`):
   ```python
   from TTS.api import TTS  # Or piper equivalent
   import subprocess  # For playback
   from langchain.agents import AgentExecutor  # Skeleton orchestration
   import whisper  # Local STT

   class NeuromancerAgent:
       def __init__(self):
           self.tts = TTS("tts_models/multilingual/multi-dataset/xtts_v2").to("mps")
           self.whisper_model = whisper.load_model("tiny")  # Fast STT
           self.vault_brain = VaultBrain()  # RAG/embeddings
           # Ollama/FL init from skeleton

       async def voice_converse(self, audio_input_path: str):
           # STT
           result = self.whisper_model.transcribe(audio_input_path)
           user_text = result["text"]
           
           # Agent response (RAG + Ollama)
           response = self.vault_brain.query(user_text)  # <500ms target
           
           # TTS
           audio_out = "temp_response.wav"
           self.tts.tts_to_file(text=response, speaker_wav="user_voice_clip.wav", language="en", file_path=audio_out)
           
           # Play (macOS)
           subprocess.run(["afplay", audio_out])
           
           # Log for FL personalization (fl_personalizer.py)
           self.log_interaction(user_text, response)
           
           return response

       def proactive_alert(self, message: str):
           # For vault changes (Watchdog trigger)
           self.tts.tts_to_file(text=message, file_path="alert.wav")
           subprocess.run(["afplay", "alert.wav"])  # Semi-autonomous notification
   ```
3. **Enhancements**:
   - **Always-On**: Launchd service (macOS); Watchdog monitors vault → proactive TTS (e.g., "Inbox processed").
   - **Personalization**: LoRA fine-tune TTS on user clips (via Flower in `fl_personalizer.py`); store voice embeddings in ChromaDB.
   - **Sandbox**: Subprocess for TTS/STT; limit file access.
   - **Latency**: <500ms E2E (Whisper tiny + XTTS stream); fallback text UI (Streamlit/Gradio).
   - **Multimodal**: CLIP for image analysis → TTS description.
   - **IoT**: MQTT (paho-mqtt) for smart home announcements (e.g., "Lights on via voice command").
4. **Testing**: Add to `tests/` (pytest for voice loop); monitor with cProfile (<200ms targets).
5. **Fallbacks**: pyttsx3 for basic TTS if XTTS unavailable; OpenRouter for rare heavy tasks (<10% usage).

**Overall Feasibility**: Seamless—~4-6GB RAM peak; aligns with local stack. Start with Piper prototype for speed, iterate to XTTS cloning. Track in `dev_log.md`.
